# COEER 毛玻璃界面分阶段重构计划

版本：`coeer-glass-v1` · 更新：2026-10-24。

P0–P4 已完成文档与前端接入；P5 已完成 Chromium 代表页面、主题、移动尺寸、交互与实验室性能验证。跨浏览器、实体手机与生产指标仍待验收；详见[实施记录](implementation-review.md)。下表保留实施依赖和回退边界。设计依据见 [UI/UX 规范](ui-layout.md)，令牌见 [design.json](design.json)。

## 实施顺序

每阶段独立提交、独立验收；先建立不透明回退，再启用玻璃。后续阶段依赖前一阶段完成，不同时混入路由、权限、接口、轮询或预约业务逻辑变更。

| 阶段 | 工作与主要目标文件 | 进入/完成条件 | 回退边界 |
| --- | --- | --- | --- |

P4A/B/C 是可分别交付的模块批次，均依赖 P3，可按回归风险逐批推进。

## 基线与检查方式

P1 前记录应用构建版本、浏览器/设备、viewport 与 workspace 宽度、主题、数据规模和效果模式。至少取首页、反馈列表与详情、空间时段与预约详情、个人中心、管理长表、Modal/命令菜单作为基线。截图与 trace 属于未来实施证据，不能用本次文档中的颜色推算代替。

每阶段只运行适用检查：令牌/样式先执行 `pnpm typecheck` 与 `pnpm build`，组件/页面改动运行对应现有回归测试；最终执行仓库的 `pnpm check`。需要补充验证时只覆盖真实交互风险，如抽屉焦点、模态内外点击、异步状态与预约提交，而不是断言 CSS 文本。预约测试按仓库测试说明使用隔离库与模拟官网。本次已执行类型、浏览器、数据库隔离集成测试与构建；结果见实施记录。

实施时优先复用现有 `coeer-*` 类与 `components/coeer`，在现有 CSS 层增加材质能力；不引入新的 UI 框架、玻璃特效依赖、背景资产或基于 UA 的设备等级判断。CSS 能力增强同时覆盖标准和 WebKit 前缀，用户偏好覆盖增强规则；最终核对 computed style，确保没有 blur 时背景仍不透明。

## 视觉可感知补充验收

针对用户反馈，已补测真实游客首页的空态与滚动状态。必须同时确认玻璃区域仍在视口内、背景存在可见层次、透明填充真实透色以及模糊后的内容可辨；不能用 computed style 或自动测试通过替代实际视觉判断。四个新增场景覆盖深浅主题与桌面/手机尺寸，具体证据见实施记录。

## 页面验收矩阵

各行均覆盖浅色/深色，以及有 blur/无 blur 的代表页面；小屏采用触屏材质。P4 先逐模块检查，P5 再检查跨模块一致性。

| 场景 | 必查页面与内容 | 通过条件 |
| --- | --- | --- |
| 桌面全宽 | 1920、1440px；首页、反馈、我的预约、个人中心、管理表 | 标题/操作/筛选/内容/分页右边界到统一页边距；无整页窄容器留下大片空白；侧栏固定 224px、顶栏 52px |
| 中间尺寸 | viewport 1024、768px；workspace 880、720、1080px 与 settings 640px 阈值两侧 | 外壳与容器断点各司其职；不因出现侧栏而强制拥挤多列；详情/设置顺序合理，无重复 padding |
| 手机与缩放 | viewport 390、320px；横屏、200% 缩放和 400%/320 CSS px 重排 | 无整页横向溢出；44px 触达、输入 16px、安全区与软键盘可用；Tabs/表格/代码/公式仅自身滚动 |
| 对比度 | 两主题画布、黑白图片滚经顶栏、导航选中项、字段、按钮/Badge、Modal | 最终合成普通文字 ≥4.5:1、必要非文本 ≥3:1；高光不代替控件边界；危险按钮前景随主题正确变化 |
| 覆盖层 | 移动抽屉、Ctrl/Cmd+K 命令菜单、确认 Modal、裁剪、Toast | 焦点进入与返回、Esc、键盘选择、真实外部点击关闭、内部留白不关闭；滚动锁无跳宽；重要反馈在活动模态中可见 |
| 长内容与媒体 | 长中文/英文标题、昵称/邮箱/URL/用途，Markdown 表格/公式/代码，深层回复，缺图/旧图/大图 | 局部限宽、换行、裁剪和 contain 正确；正文实底无模糊；渐隐展开可操作，文件名与错误不截断 |
| 真实状态 | 无数据、多条记录、首载、刷新、pending、error、disabled、权限不足、未读与已读 | 文案与服务状态一致；后台刷新失败保留已有内容；没有假 0/假统计；错误不只依赖自动消失消息 |
| 任务流程 | 反馈提交/回复、活动报名、商城兑换、抽卡、资料安全、宿舍问卷、预约慢响应 | 保留字段/权限/校验，阻止重复提交；预约先获申请号、后台继续运行、占位不误报、失败位置正确 |
| 偏好与降级 | 减少透明、增强对比、强制颜色、减少动画、不支持 blur、打印 | 表面回到实底、边界/焦点/状态完整；减少动画与减少透明分别处理；打印正文清晰 |
| 浏览器与性能 | 当前稳定 Chromium、Firefox、macOS Safari、iOS Safari、Android Chrome；标准/前缀/无支持路径 | 实机检查 sticky/top layer/backdrop 实际行为；满足 UI 规范的 backdrop 数量、LCP/INP/CLS 目标与 trace 预算；不满足即使用实底 |

## 每批交付记录

每批记录“模块、提交版本、浏览器/设备与构建、viewport/容器、主题/效果模式、数据与状态、截图/trace 位置、对比度、结果、剩余问题、回退方式”。未访问的页面、未使用的浏览器和未测得的性能指标标记为未验收。最终同步 `design.json` 的交付状态和 surface 记录，区分已定义、已实现、已验证，不把 P0 的文档完成视为整站重构完成。
