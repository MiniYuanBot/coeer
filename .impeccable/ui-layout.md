# COEER UI 与布局规范

本文件约束后续页面实现与修复。色彩和组件视觉沿用 [design.json](design.json)，
全站外壳沿用 [AppShell 设计记录](surfaces/src-app-components-coeer-layout-appshell-tsx.md)。
实际布局由 `src/app/styles/app.css` 与 `components/coeer` 公共组件实现。

## 页面骨架与铺满工作区原则

- 登录后的页面共用 `AppShell`：桌面侧栏 224px，顶部路径栏 52px。
- 内容区占满侧栏以外的全部可用宽度。桌面左右保留 32px、手机左右保留 16px 的统一页边距。
- 所有工作区页面使用全宽 `PageLayout`，宽度随窗口变化；标题、主操作、导航、筛选、分隔线和主体区域对齐相同的左右边界。
- 页面容器和工作区不设置 704px、896px、1200px、1440px 等固定最大宽度，不因个人资料或预约页面类型而收窄整个页面。
- 页面区块间距为 24px，分栏间距为 32px。子页面继承父路由的可用宽度，不重复添加外层 padding 或居中容器。
- `SectionHeader` 承担唯一 h1、简短说明和主要操作。主操作靠工作区右侧，手机空间不足时换行。
- 模块导航由父路由提供，同一模块只出现一次，并与当前页内容等宽。

| 页面任务 | 宽屏布局 | 窄屏布局 |
| --- | --- | --- |
| 反馈列表、空间目录等集合页 | 列表、筛选和分页铺满工作区，标题、状态、时间分列对齐 | 次要信息收进记录内部 |
| 我的预约 | 空间与用途、日期与时段、状态与结果三列，使用全部可用宽度 | 单列记录 |
| 个人中心 | 身份与积分摘要按 2:1 分配；账户设置与积分记录按 3:2 分栏 | 摘要和各分区按顺序纵向排列 |
| 反馈详情、预约详情、带说明的表单 | `DetailLayout`：主体自适应，右侧承载反馈信息、处理进度或填写说明，宽度在 280–400px 内变化 | 主体与相关信息叠放 |
| 独立新建与编辑表单 | 页面及表面全宽；字段根据内容分组，局部输入区可限制宽度 | 标签、输入和操作自然换行 |

可读性在区域内部处理：长段落可限制为约 70–80ch，昵称和密码输入区可限制为 704px。
这些局部限制不缩小页面容器；右侧空间用于真实的状态、记录、相关信息或任务说明。
页面高度跟随真实内容，空状态保留简短引导。

## 响应式分栏

- 以 `workspace` 容器的可用宽度决定分栏，窗口宽度不直接等同于内容宽度。
- 详情与预约列表在工作区达到 880px 时分栏；个人中心在达到 1080px 时并排展示设置与积分记录。
- 个人中心设置区域使用独立的 `settings` 容器，区域达到 640px 时才将说明与表单分成两列。
- 栅格弹性列使用 `minmax(0, 1fr)`，长昵称、邮箱和用途可以换行，避免内容撑宽页面。

## 内容层级与公共组件

- 延续白色画布、冷灰导航、石墨文字和低饱和紫色主操作。颜色使用语义令牌，兼容深浅主题。
- 页面标题 22px；设置分区与记录标题 14px；正文 13–14px；时间与辅助信息 12px。
- 表面保持平面。身份摘要等独立信息可使用 `Card`，8px 圆角、16px 内边距；记录列表使用行和分隔线。
- 相邻摘要卡片间距 16px；普通区块间距 24px。避免额外嵌套卡片和重复边框。
- 按钮、输入框、字段标签、徽章、提示和空状态复用 `components/coeer`，不另建一套样式。
- 每个任务区只突出一个主操作；辅助操作用 outline/secondary，危险操作使用明确文案和确认步骤。
- 记录采用 `coeer-record-list`、`coeer-record-row`：上下细分隔线，行内垂直留白 16px，标题和状态先行，时间与说明随后。
- 整行可点击的记录保留键盘焦点；不可点击的积分记录不伪装成链接。状态同时显示文字和语义色。

## 个人资料与表单

- 个人中心依次展示标题、身份与积分摘要、资料设置、账户安全、最近积分流水。
- 设置分区复用 `SettingsSection`，根据自身区域宽度分栏；账户设置与右侧积分记录共同占满工作区。
- 每个字段有可见标签；说明紧邻字段，提交结果留在所属表单内。昵称、邮箱等长内容必须换行。
- 提交期间保持表单内容稳定并禁用相关控件。成功、失败和处理中状态分别表达，不用笼统成功提示掩盖等待。
- 密码链接锚点指向对应设置标题；手机上字段字号至少 16px，控件和按钮触达高度至少 44px。

## 预约提交与详情

- 本地身份、权限、参数和冲突校验通过后，先持久化预约及后台任务，立即返回申请号并进入详情页。
- 官网核验、提交、审批和取消结果在详情页更新。排队或已受理不能显示成已确认。
- 提交期间停止原时段选择页的空闲轮询和选中时段失效检查，并禁用编辑，避免把自己的占位误报为冲突。
- 详情页刷新或关闭不影响后台处理；重复提交相同幂等键必须复用原申请。
- 本地校验失败且未生成申请号时，在原表单显示原因；已有申请号的失败进入详情查看。
- 轮询失败保留已加载的预约信息并显示提示。没有记录、权限不足和加载失败分别展示。

## 验收

- 至少检查 1920px/1440px 桌面、约 1024px 中等屏幕与 390px 手机。每个页面的主体右边界应到达统一页边距，不出现固定窄容器留下的整块空白；窄屏不得出现整页横向溢出。
- 检查深浅主题、长昵称/用途、空记录与多条记录、加载及错误状态。
- 检查慢速官网响应：进入详情页时官网仍在处理，最终结果自动更新；原页面不出现自己的占位冲突提示。
- 检查键盘焦点、表单标签、移动导航、主要操作和密码锚点可用。
- 预约验收使用隔离数据库与模拟官网，避免向真实官网提交测试预约。
