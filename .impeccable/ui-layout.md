# COEER 毛玻璃 UI/UX 规范

当前契约：`coeer-experience-v2` · 更新：2026-10-25。本文集中维护当前界面规则，历史修订见 Git。

## 1. 适用范围与文档关系

本规范覆盖游客入口、认证、登录工作区和管理后台。§1–10 记录公共规则与已有业务约束；§11–17 补充本轮体验规则。语义角色、全宽、实底正文与降级机制沿用；背景、玻璃和模态切换已按 §17 校准。实施完成与验证范围分别记账，不把 Chromium 页面检查扩大为跨平台或生产验收。

- [PRODUCT.md](../PRODUCT.md) 定义产品能力、权限与业务约束；本次不改变这些边界。
- 本文件是视觉、布局、交互、模块应用与效果降级的规范。
- [design.json](design.json) 的 `extensions.colorMeta[*].canonical` 保存颜色值，`extensions.tokens` 保存排版、圆角、布局、材质、组件与预算令牌，投影/动效/断点保留在 schema v2 的 `extensions.shadows/motion/breakpoints`；`components` 是文档预览示例，不是已交付的 React 组件。
- [DESIGN.md](../DESIGN.md) 是同步的设计入口，frontmatter 是上述令牌的可读镜像，不单独定义另一套数值。
- 外壳统一使用 AppShell、Sidebar、CommandMenu 与 useDialog；尺寸、材质和浮层行为见 §4–7。

后续修改先更新本规范和 `design.json`，同步 `DESIGN.md` 的令牌镜像。业务语义服从 `PRODUCT.md` 和现有 contracts/services，视觉与布局服从本版本规范；源码与规范不一致的部分列入重构，不反过来用旧代码覆盖新规范。

`design.json.extensions.contract` 与 `extensions.tokens` 记录当前实现，`extensions.experienceRevision` 保存本轮应用规则、实施状态和验证边界；旧契约保留于 `contractHistory`。材质值与 CSS、DESIGN 镜像同步，历史参数不再作为当前目标。`.impeccable/config.json` 的 `buildPath: code` 沿用。

## 2. 方向与现状依据

方向是低饱和紫灰画布、静态柔和渐变、半透明导航与浮层，以及稳定的实底正文。延续现有紧凑导航、清晰工具栏和列表密度。玻璃用于表达导航与覆盖关系，正文通过实底、对齐和留白保持阅读清晰。

## 3. 色彩、主题与令牌消费

颜色数值见 `design.json` 的 `colorMeta`，深色键以 `dark-` 开头。页面消费同一语义角色，由根主题覆写，不能在业务页另写浅色/深色色值。沿用现有 `--background` 等 HSL 三元组和 `hsl(var(--token))`，与 Tailwind 4 的现有 `@theme inline` 映射兼容。新增透明度只作用于表面背景，不对含文字的整个元素设置 opacity。

| 角色 | 用法 |
| --- | --- |
| `background`、`canvas-tint-a/b` | 紫灰画布及最多两处静态渐变；不承载状态语义。 |
| `card` / `card-foreground` | 实底正文、内容卡、表格与字段所在表面；与画布轻微分离。 |
| `sidebar`、`chrome`、`overlay` | 分别用于导航不透明回退、玻璃导航底色、浮层底色；透明度由材质令牌决定。 |
| `foreground`、`muted-foreground` | 正文和次要信息；正文不因玻璃效果降低文字透明度。 |
| `muted`、`border` | 辅助分区、hover 与装饰分隔；`border` 不承担控件唯一边界。 |
| `control-border`、`ring` | 可交互控件边界与键盘焦点，须满足非文本对比度。 |
| `primary` / `primary-foreground` / `primary-hover` / `primary-soft` | 主要操作、链接、焦点与轻量选中背景；按钮 hover 用明确实色，不降低按钮整体透明度。 |
| `success/warning/danger` 及各自 `*-soft` | 保留业务状态语义；状态底色是主题内不透明浅底，搭配状态文字和图形。 |
| `danger-foreground`、`danger-hover` | 危险按钮的主题内文字与 hover。 |
| `inverted` / `inverted-foreground` | 兼容既有反相场景，不能用硬编码黑白替代。 |
| `glass-highlight` | 细高光边缘的基色；高光透明度和 inset 线由材质定义，不替代可见焦点。 |

首次访问仍默认浅色；尊重并保留 `coeer-theme` 中用户明确选择的深浅主题，首帧前应用，避免闪白。不在本次设计中加入“跟随系统”第三种主题或新设置入口。字体加载失败时直接使用系统回退，不阻塞阅读。

画布只有一层背景，最多两个 radial-gradient，色彩与 alpha、位置见 `extensions.tokens.canvas`。画布使用 `body::before` 的固定视口背景层，`pointer-events: none` 且不参与 blur；不能让渐变随整页高度被拉平或滚走，避免空态和长页的导航背后没有可感知的层次。不使用大面积品牌紫、不增加第三方背景图片、视频、噪点贴图、漂浮光球或持续渐变动画。正文、图片和状态色不受画布滤镜影响。

## 4. 材质与层级

本节是本轮校准后的当前材质值；画布与投影完整值见 `design.json`。§17 保留专项核查方法，结果与未测环境见本轮实施记录。

以下 alpha 均为背景填充的不透明度。所有常规边框 1px；高光只是一条内侧顶边，不叠加外发光。

| 材质 | 浅色 / 深色背景 | 桌面 blur | 触屏或小屏 | 边缘与投影 | 允许位置 |
| --- | --- | --- | --- | --- | --- |
| Canvas | `background`，alpha 1 | 0 | 保留静态低对比渐变 | 无 | 根画布 |
| Chrome | `chrome`，alpha .68 / .72 | 16px | alpha .84 / .88，blur 8px | 高光 .56 / .16，`shadow-chrome` | 桌面侧栏、顶栏、游客页头 |
| Floating | `overlay`，alpha .80 / .84 | 20px | alpha .88 / .90，blur 8px | 高光 .64 / .20，`shadow-floating` | Modal、移动抽屉、命令菜单、Toast、实际存在的弹出菜单 |
| Reading | `card`，alpha 1 | 0 | 同桌面 | 无可见外框、无投影；高对比模式恢复边界 | 正文、信息流、表格、表单、详情辅助信息 |
| Subtle | `muted`，alpha 1 | 0 | 同桌面 | 必要时用分隔线，无投影 | 表头、代码块、统计格、空状态背景 |

细则：

- 普通 `Card` 默认无可见外框、无投影，以接近画布的实底分区；浅色画布/卡片明度97/99，深色13/15.5。标题条不单独加深底色，内部只保留细分隔。普通 `Card` 始终默认 Reading；不能通过修改 Card 全局默认使所有业务内容变成玻璃。表面内的字段、状态 Badge 与长文使用实底。
- Chrome 与 Floating 内将次要文字、焦点与控件边界映射至 `chrome-muted-foreground`、`chrome-ring`、`chrome-control-border`；正文继续消费原角色，字段保持实底。两种玻璃均需按最终合成背景检查对比度。
- 外壳贴边，不为侧栏和顶栏添加漂浮外边距或整页圆角。普通容器圆角 12px，浮层 16px，控件与导航项 8px，徽章/键帽 4px；头像、状态点保留圆形。
- 内容卡 hover 只改语义背景或边界，不位移、不放大、不自动增加投影。Chrome 和 Floating 的投影随主题切换，深色通过较弱高光与遮挡关系分层，不使用紫色光晕。
- NavTabs 与 FilterPanel 直接置于画布，保留选中下划线和必要细分隔；不再包一整条对比明显的实底面板。内容区仍实底，不增加嵌套 blur。
- 遮罩使用主题内 `scrim`：浅色 `hsl(252 20% 10% / .36)`，深色 `hsl(252 25% 3% / .60)`，本身不模糊。浮层内容有长文、裁剪图像或密集表单时，内部阅读区保持 Reading。
- 不对父容器设置 `filter: blur()`；backdrop-filter 只影响背后画布。玻璃层不包围整个工作区，避免创建异常的 fixed/sticky 包含块和额外合成层。

层级令牌：内容 0，局部 sticky 20，顶栏 30，桌面侧栏 40，页面进度 60，普通 Toast 70，跳转链接 100。原生 modal dialog 进入浏览器 top layer，层级高于上述 z-index；不能靠 Toast 的 z-index 覆盖它。模态期间将属于当前任务的错误/结果放在 dialog 内，并在活动上下文中播报；不得将重要错误只留在被遮挡的 Toast。

## 5. 全宽布局与响应式

工作区占满侧栏之外的全部可用宽度。页面容器不设 704/896/1200/1440px 等固定最大宽度；标题、操作、模块导航、筛选、主体和分页共用左右边界。现有公开页 `.coeer-container` 与认证页的局部宽度不改变登录工作区规则。

| 项目 | 规则 |
| --- | --- |
| 桌面外壳 | viewport ≥1024px 显示 224px 固定侧栏；顶栏 52px，保持 sticky。 |
| 页边距 | viewport ≥640px 左右 32px、上下 28/64px；<640px 左右 16px、上下 24/48px。 |
| 页面结构 | 全宽 PageLayout；SectionHeader、父路由提供的一次模块导航、筛选/提示、主体、分页。已有父导航先于子标题的模块保留 DOM 顺序，避免视觉与键盘顺序分离。 |
| 间距 | 4px 基准；令牌提供 4/8/12/16/20/24/32/40/48/64px。紧凑控件可用既有 6/10/14px 内边距。区块间 24px、分栏 32px、卡片间 16px。 |
| 正文与输入 | 仅在内部限制：长文约 70–80ch，默认 76ch；账号字段区最多 704px。容器与表面仍全宽，余下空间只放真实的相关信息，不为填空制造内容。 |
| 详情 | `workspace` 容器 ≥880px：`minmax(0, 1fr)` + `clamp(280px, 26%, 400px)`；不足时堆叠。辅助栏 sticky 顶距 76px，超出可视高度时取消吸附。 |
| 首页 | `workspace` ≥880px：主栏自适应 + 264px 信息栏；不足时顺序堆叠。 |
| 个人中心 | 摘要在 `workspace` ≥720px 按 2:1；设置与记录在 ≥1080px 按 3:2；`settings` 自身 ≥640px 才将分区说明与字段分栏。 |
| 表单与编辑器 | `admin-form` ≥560px 两列；`markdown-editor` ≥720px 编辑与预览并排；更窄单列。 |
| 集合 | 普通卡片最小 280px、收藏卡片最小 200px，使用 `minmax(min(100%, n), 1fr)` 自适应；不能仅按 viewport 强制三列。 |
| 移动导航 | viewport <1024px 使用 dialog 抽屉，宽 `min(288px, 86vw)`，高 100dvh，导航区独立滚动，用户与主题区可达。 |
| 公开与认证 | 游客页头 64px、sticky 顶距 0，滚动后仍保留玻璃导航；公开容器沿用当前 84rem 上限及桌面 24px/手机 16px 留白。认证字段区最多 340px，居中、实底；长错误可换行。此例外不扩散至工作区。 |

分栏判断以内容容器宽度为准，只有外壳显隐与全局页边距采用 viewport。所有弹性列使用 `minmax(0, 1fr)`、内容子项 `min-width: 0`；昵称、邮箱、用途、URL 允许换行。唯一 h1 由页面/模块父级承担，群组内子页使用 h2。

移动布局要求：

- 标题与多个操作在空间不足时自然分行，搜索独占一行；日期字段、筛选和操作不挤压标题。Tabs 只滚动自身，表格/代码/公式只在局部滚动，不出现整页横向溢出。
- 手机或 `pointer: coarse` 的交互控件触达区域至少 44×44px；密集按钮可保持小图标，但命中区域不能缩小。输入、选择器、文本域至少 16px 字号，保留浏览器缩放。
- 固定提示和底部操作考虑 `env(safe-area-inset-*)`；软键盘打开后字段与提交按钮可见，避免多个固定底栏遮住正文。
- 桌面 body 负责页面主滚动，侧栏导航自身滚动；dialog 仅内容区滚动并锁定背景，关闭后恢复原滚动位置，避免工作区发生宽度跳动。

## 6. 字体、可读性与交互

字体沿用 Inter、`-apple-system`、BlinkMacSystemFont、Segoe UI、PingFang SC、Microsoft YaHei、sans-serif；不开启额外展示字体。中文正文不施加负字距，日期、积分、表格数值使用 tabular-nums。

| 角色 | 字号 / 字重 / 行高 | 用途 |
| --- | --- | --- |
| display | 32px，宽屏 44px / 600 / 1.35 | 游客介绍，不扩散到工作区 |
| headline | 22px / 600 / 1.4 | 页面 h1；认证标题沿用 25px 局部变体 |
| section | 14px / 600 / 1.5 | 设置、记录、侧栏分区标题 |
| title | 15px / 500 / 1.5 | 帖子、活动、群组标题 |
| body | 14px / 400 / 1.7 | 列表与基础阅读 |
| reading | 16px / 400 / 1.8 | 详情长文、Markdown 正文 |
| copy | 13px / 400 / 约 22px | 简短说明 |
| label / field | 13px / 500 或 400 / 1.5 | 操作与桌面字段；触屏字段 16px |
| caption | 12px / 400–500 / 18px | 元信息和 Badge，不承担长文 |

可读性是验收门槛：

1. 按 WCAG 2.2 AA，普通文本（含次要信息、placeholder、状态和链接）与最终合成背景至少 4.5:1；大字至少 3:1。正文推荐达到 7:1。不能只计算未合成的颜色令牌。
2. 控件唯一边界、必要图标和焦点与相邻背景至少 3:1；装饰高光与分隔线可更弱，但不承担唯一识别作用。字段使用 `control-border`，不只使用 `border`。
3. 玻璃背后的内容可能滚动，验收须覆盖画布两端、黑/白图像、正文滚动经过顶栏等最不利背景。Chrome 上标签使用 foreground/muted-foreground，选中项用实底 primary-soft + primary 或前景文字；语义色文字放在实底状态底上，不能直接叠在任意玻璃背景上。
4. 玻璃文字按实际合成结果抽查，当前颜色修订后的结果见本轮视觉记录。实底字段通过 field-border 消费主题边界，不继承玻璃的强边界；普通内容面板不画装饰外框。
5. focus-visible 为 2px ring、3px offset；密集行或 Tabs 可内描以避免裁切。遮罩、sticky 顶栏和固定提示不能遮住当前键盘焦点。所有图标操作有可访问名称，状态不只靠颜色区分。
6. Modal/抽屉/命令菜单打开时聚焦其内、限制背景交互，关闭后还原触发点；Esc 和关闭按钮可用。只有真实边界外的点击才关闭，内边距点击不关闭；有未提交内容或危险操作时保留原有确认流程。
7. 页面导航用链接及 aria-current；切换面板才使用 tab 语义；筛选按钮使用 aria-pressed。命令菜单保留 Cmd/Ctrl+K、方向键、Enter、Esc；打开前关闭移动抽屉，避免双层模态。
8. 提交中保留文案和原表面尺寸，显示真实 pending 与 aria-busy，禁用重复提交；错误关联字段并保留输入。首次加载、后台刷新、空内容、权限不足、网络失败分别表达。背景刷新失败保留已有内容，避免全页清空。

交互颜色过渡 120ms ease-out，按钮 150ms ease-out；浮层仅允许最长 160ms 的 opacity 和不超过 4px 位移。禁止 blur、box-shadow、背景位置的动画以及 `transition: all`。`prefers-reduced-motion: reduce` 下去除位移和非必要动画，状态颜色即时切换；真实加载同时有文字，不依赖旋转动画。

## 7. 公共组件契约

优先复用以下组件；页面组合与管理列表的实现契约见 §18。

| 公共组件 | 材质与布局 | 必备状态/行为 |
| --- | --- | --- |
| AppShell / Sidebar / ThemeToggle | 共享 Canvas 与 Chrome；固定尺寸见 §5；不增加外壳留白 | active/hover/focus、长用户名、移动抽屉、主题首帧；导航能力与角色权限保持现有定义 |
| PageLayout / SectionHeader / DetailLayout / SettingsSection | 全宽；内部行宽与容器分栏；层次用留白和分隔 | 唯一主标题、操作换行、长文、辅助栏堆叠；子路由不重复 padding |
| Card / StatsBar | Reading；Card 不强制统一内边距，常用 16/20px；StatsBar 一体分格 | 无 hover 位移；真实数据、未知数值用占位/加载而非伪造 0 |
| Button | 实底 primary/secondary/danger，outline/ghost 继承所在实底或 Chrome 的安全区域；8px 圆角 | 默认 36px，xs 28、sm/icon 32、lg 44；触屏至少 44×44；hover/focus/disabled/loading 均可辨，loading 保留标签；danger 用独立前景色 |
| Field / Input / Textarea / Select / SearchInput | Reading 输入底、control-border；标签常驻、说明在控件后；搜索图标占位 32px | 默认 36px，认证与触屏 44px；error/readonly/disabled/focus，关联错误/帮助；原生选择器行为优先，不支持 base-select 时用原生菜单 |
| Badge / Alert | 实底主题语义浅底，短状态不收缩不拆字；提示可换行 | success/warning/danger 搭配文字或图标；错误有 alert 语义，普通状态用 status，不反复抢读 |
| FilterPanel / NavTabs / Pagination | Reading 或无额外表面；线性排列、可换行；Tabs 只滚自身 | 筛选选中与清除、首尾页、无结果；键盘焦点和主题一致；不增加新的 sticky 玻璃条 |
| FeedbackCard / coeer-record-list / coeer-record-row | 反馈目录使用独立状态卡片网格，普通记录使用行与分隔线 | 手机状态/日期收进元信息；整卡链接有焦点，不嵌套按钮；纯记录不伪装为可点击 |
| Markdown / MarkdownEditor / PostContent / ReplyThread | Reading；长文 foreground、16px/1.8、76ch；编辑/预览按容器分栏 | 保留 GFM、公式、代码、链接与本地横向滚动；摘要渐隐和展开可键盘操作；深层回复减少缩进并保留层级提示 |
| MediaPreview / ImageUploadField / ImageCropper / CollectibleCard | 图片保持真实色彩，不施加玻璃滤镜；裁剪内区实底 | 加载/缺图/失败有占位；本地选图、拖入、预览、裁剪、移除及原生键盘行为；比例见 §8 |
| TableScroll | Reading 表头与单元格；必要 sticky 表头也使用实底 | 只滚容器、可访问名称、键盘滚动与溢出提示；排序/操作不能仅 hover 可见 |
| Modal / CommandMenu / 移动抽屉 | Floating + scrim；阅读或表单内区实底；Modal 512px、命令菜单 560px、距屏至少 16px | top layer、滚动锁、焦点管理、内外点击判定；命令菜单顶部位置桌面 16vh/手机 10vh，不超出可视高度 |
| Toast / EmptyState / LoadingState / PageStatus | Toast 为 Floating；空与加载态 Reading；页面进度不占文档流 | Toast 用 live region、无焦点抢占；普通信息目标显示至少 5s、hover/focus 暂停并可关闭；需用户处理的错误持久内联，不能仅依赖自动消失消息；仅真实 pending 显示进度 |

## 8. 分模块应用规则

所有模块共享外壳。下表中的“实底”均指 Reading/Subtle；业务字段、权限和状态转换不由视觉重构重新定义。

| 模块 / 路由 | 应用规则 |
| --- | --- |
| 游客首页 `/`、登录/注册/找回/重置密码 | 游客页头可用 Chrome，介绍区保留柔和背景；认证字段区实底，不把密码输入放在透出图像的玻璃上。保留表单错误、返回入口与已有登录跳转语义。 |
| 登录首页 `/` | 保留“官方公告 → 最新动态 → 近期反馈”，每段最多 5 条，不在首页分页；公告置顶优先，最新动态由已审核公开群组帖子和活动按发布时间倒序混排，忽略群组置顶；不新增回复框。整个段落实底，段内分隔，不逐条叠加玻璃卡。首页正文预览 140px，可展开；信息栏承载真实积分、群组和活动。 |
| 群组、帖子、回复 `/groups/**` | 群组目录为实底弹性网格；群组父级标题和导航只出现一次。帖子列表与详情区分摘要/长文；保留帖子点赞、收藏、成员/入群/审核与发帖权限。公告及每群组帖子各最多置顶 5 条，原有折叠规则保留。回复区实底、深层缩进受控。 |
| 公告 `/bulletins/**` | 列表实底，置顶标记有文字；详情长文控制局部行宽。订阅状态与阅读信息使用既有能力，不让装饰效果抢过公告内容。 |
| 站内通知 `/notifications`、收藏 `/bookmarks` | 通知列表和收藏内容实底；未读有文字/图形，不能只靠紫色圆点；读/未读、失效目标、空列表与加载失败分别表达。通知铃铛继续跳转现有通知页，不凭设计稿新增弹出收件箱。 |
| 反馈 `/feedbacks/**` | 集合使用独立状态卡片网格；分类、状态、日期对齐，手机收进元信息。详情正文与处理信息分栏，日志实底；新建/回复的 Markdown 编辑器实底。待审核、处理中、完成、拒绝等标签保持真实服务语义。 |

| 空间目录与预约 `/spaces/**` | 日期、筛选、时段矩阵、容量与申请表全部实底；选择、已占用、不可用、同步中同时有文字/图形及对比清晰的边界。我的预约全宽三列记录，窄屏堆叠；详情用 DetailLayout，任务进度、失败原因与结果可持续阅读。旧 account/identity/login 等兼容路由沿用当前跳转，不设计重复身份入口。异步契约见下。 |
| 宿舍 `/dorms/**` | 批次、问卷、匹配/确认结果分区实底；问卷按真实分类组织，必填、校验与提交结果可见。个人信息和敏感需求不作为半透明装饰背景；保持当前角色可见性，不因重排暴露额外信息。 |

| 个人中心 `/profile/**` | 全宽身份与积分摘要、设置、安全、记录；按 §5 分栏。字段局部可限 704px，积分记录保持行结构；说明与字段关联，表单结果留在所属分区。密码锚点指向对应标题，不被顶栏遮挡；未知统计不填静态数值。 |
| 管理 `/admin/**` | 共用 Chrome 外壳与现有管理导航；工作台、群组审核、反馈、公告、活动、宿舍、商城、卡片、成就、用户统计的表格和编辑区全部实底。操作可由键盘/触屏发现；审核、删除、批量操作保留确认和真实状态，切换编辑对象须正确更新字段值。 |
| 预约管理 `/admin/spaces/**` | 总览、目录配置、预约与异常、白名单、任务与审计继承管理实底规则；日志与任务表局部滚动。暂停、只读、接入错误与真实预约状态分别呈现，不以视觉重构改变同步、轮询、权限或写入开关。 |

预约异步 UX 契约继续有效：本地身份、权限、参数、冲突校验通过后，先持久化预约与后台任务，返回申请号并进入详情；排队/受理不能显示为已确认。提交期间停止原时段选择页的空闲轮询和失效检查并禁用编辑，避免把自己的占位报成冲突。刷新或关闭详情不影响后台任务，相同幂等键复用申请。未生成申请号的错误留在原表单，已有申请号的失败进入详情；轮询失败保留已有数据和提示。验收使用隔离数据库与模拟官网，不向真实官网提交测试预约。

图片上传保留“选择本地文件”、带虚线边框的文件区、预览/文件名/大小/裁剪/移除；URL 入口保留在展开项。本地拖入只改变边界和实底，不开启 blur。裁剪支持拖动、缩放、方向键和重置，按上述规格输出 PNG；手机裁剪区不超过视口高度 32%，取消保留原图。

## 9. 性能预算与效果降级

增强按“先实底、再能力检测”实施，首屏就应可读。默认先使用 `sidebar` / `overlay` 不透明回退和边框；只有 `@supports` 检测到标准或 `-webkit-backdrop-filter` 才应用对应玻璃背景。使用前缀只为兼容，不能对同一层叠加两次模糊。

| 条件 | 要求 |
| --- | --- |
| 支持 blur、正常桌面 | Chrome 16px、Floating 20px；常驻 backdrop 区域最多 2 个（侧栏/顶栏），单个浮层打开时总数最多 3。 |
| viewport <640px 或 pointer: coarse | 使用触屏材质的更高 alpha、8px blur；同时可见的 backdrop 区域最多 2。打开模态时优先关闭/停用后方导航的 blur；抽屉与命令菜单互斥。 |
| 不支持 backdrop-filter、增强样式未加载 | 不透明 `sidebar` / `overlay` + 普通边界；不允许留下低 alpha 的“透明但不模糊”版本。 |
| `prefers-reduced-transparency: reduce`（支持时） | 所有玻璃改为不透明回退；blur 为 0，移除画布渐变和内高光；保留必要边界与焦点。不能只依赖此媒体查询提供兼容。 |
| `prefers-contrast: more` | 实底、无渐变/blur，增强控件边界，去除装饰高光和投影；文本、状态和焦点仍有明确层级。 |
| `forced-colors: active` | 使用 Canvas/CanvasText、ButtonFace/ButtonText、Highlight 等系统颜色；关闭渐变、blur、投影，不禁用系统颜色调整；保留边框、下划线、焦点和状态文字。 |
| `prefers-reduced-motion: reduce` | 按 §6 去除动画；与透明度偏好独立处理，减少动画不自动代表减少透明。 |
| 实测掉帧或合成成本超预算 | 先将所有 blur 置 0、提高到不透明回退，再移除画布渐变和装饰投影；结构、状态、焦点、主题与所有任务仍可用。性能模式只需样式能力钩子，不要求新增产品设置页或设备识别逻辑。 |
| 打印 | 白底深字、无渐变/blur/投影，隐藏无关导航和遮罩；保留标题、正文、状态文字、表格边界与必要链接信息。 |

不得在列表行、卡片网格、表格单元格、输入框、图片或全屏遮罩上使用 backdrop-filter。不得嵌套玻璃、使用超过 20px 的 blur、常驻 will-change 或为了玻璃增加 canvas/WebGL/运行时视觉库。静态渐变不使用 background-attachment: fixed，不随滚动或指针变化；长列表继续沿用现有分页，图片懒加载与固定比例，避免增加布局偏移。

实施后与同设备、同数据、同构建和同交互的实底基线比较：

- 设计目标为生产 p75 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1；无真实采样时只能标记为目标，不能宣称达成。
- 浏览器 trace 检查滚动、开关抽屉/命令菜单/Modal 和主题切换：桌面 60Hz 的滚动帧间隔 p95 目标 ≤20ms，代表性移动设备 ≤33ms；同一场景帧间隔 p95 不应比实底基线增加超过 10%。设备与数据固定，记录真实耗时，不用 Lighthouse 非性能分数代替。
- 玻璃样式不能引入 >50ms 的新增主线程长任务；静止页面无持续动画/重绘，开关浮层不产生由样式引起的 CLS。若基线本身未达标，分别记录既有问题与新增成本，并默认以实底交付该场景。
- DevTools 检查实际可见 backdrop 数量、合成区域和 paint；局部滚动不应因玻璃触发整个内容区持续重绘。超预算直接按上表降级，不以更高设备配置作为唯一解决方案。

## 10. 验收入口

必须进行视觉可感知验收：玻璃区域在首屏与滚动后都应可见，能辨认背景透色、边缘层次以及内容经过顶栏时的模糊。不能仅凭 computed style 中存在 backdrop-filter 或测试通过就认定效果完成；游客首页空态与暗色主题尤其需要实际截图核对。

后续每一批实施必须覆盖深浅主题、正常增强/无 blur/高对比/减少动态效果、键盘与触屏。至少检查 viewport 1920/1440/1024/768/390/320px；容器阈值检查断点两侧。200% 缩放能完成任务，400%/320 CSS px 下正文重排且只有表格、代码、公式等必要区域局部横滚。

真实空态、长标题/昵称/邮箱/用途、长文与公式、缺图、loading/error/disabled/pending/成功、断网与慢响应均需验证。没有未读通知、预约或积分时，不用示例数据填充页面。完整页面矩阵、分批目标、基线与回退记录见重构计划（本地报告，不入库）。

## 11. 欢迎区与工小成

欢迎区采用中性紫灰画布和现有静态 CSS 环境渐变。工小成使用 `/minigong.png` 的独立透明图片，与文字在同一内容网格中排版；图片完整、原色，不套商品比例、不铺满背景、不在图上叠正文。沿用现有品牌标志，吉祥物不替代导航中的 COEER 标志。

| 场景 | 构图与目标尺寸 | 信息与顺序 |
| --- | --- | --- |
| 游客，viewport ≥640px | `minmax(0,1fr) auto` 两列、顶部对齐；角色位于右上，宽 `clamp(140px,18vw,220px)`；间距32px、上下48px | 标题与工小成顶部齐平，标题和操作在左，角色右边缘贴欢迎区内边界，不居中 |
| 游客，viewport <640px | 标题与88px角色同一行、顶部对齐；说明和CTA跨两列置于下方；间距16px、上下32px | 不把角色排到CTA下方；390×844第一段公开内容标题仍须y≤640px，文字放大允许自然增高 |
| 登录首页 | 全宽内部紧凑布局；角色桌面宽 80px、手机 56px；欢迎区不设固定高度裁切文字 | 保留“动态”唯一 h1、原信息流顺序和每段最多 5 条；简短欢迎语与快捷入口不盖过内容 |
| 其他站内页、后台、认证 | 沿用任务标题、说明与实底表单 | 不复制大欢迎区；工小成不占用筛选、数据表或密码字段的空间 |

可用文案样例：“让学院生活，多一点参与。”；说明“看公告、聊想法、提建议，也能参与活动、积累成长积分。”只承诺已有能力，不写“智能助手随时解答”。具体用户内容、公告标题和群组介绍不因统一文案而重写。

图片设置固有 `width=1160`、`height=1355`，CSS 自适应、`object-fit: contain`、不拉伸。先按透明外边界确认视觉对齐，再调整图片所在网格，不用负位移让图片压住按钮。若角色只作欢迎装饰且附近已有名字，使用空 alt；若独立传达身份，alt 为“工小成，学院社区吉祥物”。不创建无功能的可点击形象。

原图约 1MB，本轮只使用现有素材；以后若制作更小版本，须保留透明度与原图，不引入远程图片依赖。首屏尺寸预留空间，图片失败仍保留标题和 CTA，删除角色后任务可完成。深浅主题检查透明边缘、残点与细节，必要的素材清理另列资产任务；不通过给整幅图片加白色底板掩盖边缘。默认静态，不增加悬浮、摇摆或连续发光。

## 12. 导航、查看范围与筛选

信息层级依次为模块导航、查看范围、条件筛选、结果与分页。层级由任务决定，不通过给每层再包 Card 或添加毛玻璃条区分。

这些相邻主区块统一使用 `--section-gap: 24px`。`FilterPanel` 内部的范围页签与工具栏也遵循同一间距，由公共样式负责；页签独立于面板时，由页面布局提供 24px，不再叠加工具栏 margin。通知页不额外包 `my-*`，管理编辑器的页签至列表/表单同样使用该令牌。卡片内部与表单字段间距仍按各自密度规则，不批量改为 24px。

| 层级 | 适用例子 | 表达规则 |
| --- | --- | --- |
| 模块子导航 | 群组主页/成员/帖子；空间目录/我的预约；预约管理五个子页 | 父路由只渲染一次 NavTabs；路由链接用 aria-current。沿用已有父导航先于子标题的 DOM 顺序，不为统一外观搬动键盘顺序 |
| 查看范围或视图 | 群组我加入的/我管理的/公开的/申请中；卡片/成就进度；反馈公开/我提交的 | 单独一行，使用清晰的实底选中或底线；不与“类型/稀有度”混在同一组。若仍用 query 按钮，保留 aria-pressed；只有真正切换 tabpanel 时才用 tab 语义 |
| 条件筛选 | 类型、状态、稀有度、日期、人数、关键词 | 使用 FilterPanel；标签为中性说明，选中项才强调；不让每组标题的紫色竖线与选中项争夺注意力。不同条件保持已有单选/查询语义 |
| 结果辅助 | 工具栏内固定清除入口、真实结果数、排序（已有时） | 不显示已选条件摘要行；选中值由控件自身呈现。清除入口固定占位，无条件时禁用；清除后保留模块/查看范围并回第一页 |

反馈与群组后台使用“已审核 / 审核队列”，旧待审核 URL 保留兼容跳转；不重复嵌套同义范围页签。

手机规则：

1. 搜索与固定清除入口同排，条件另排，命中区域至少 44px；查看范围独立一行，可在自身区域横滚，当前项进入可见范围。不能把范围项藏进条件面板。
2. 条件组超过 6 项，或按 44px 触达换行超过两行时，不默认铺开全部选项。单选组优先采用带标签和当前值的原生 Select；复杂条件复用现有 Modal，不新增视觉组件库。收起入口如“成就类型：全部”。
3. 以成就长筛选为代表，390×844 默认状态下，筛选工具栏自身（含搜索，不含范围导航及其 24px 区块间距）目标高度 ≤160px；不靠裁切文字、隐藏条件或缩小触达区达成。320px 或大字体允许合理增高，但不退回整组无限换行。
4. 若使用面板，打开时带入当前值，取消不改 query，应用后保留关键词和查看范围并回第一页；只添加前端草稿交互，不发明多选或后端参数。面板内长列表独立滚动，应用/取消与软键盘、安全区兼容。
5. 收起后由 Select 当前值显示条件，“清除筛选”固定在工具栏；只保留一个主操作层级。筛选无结果提供清除入口，首次空内容说明原因，加载失败保留旧列表与重试。

## 13. 三类模块的密度与图片规则

| 应用类型 | 模块 | 布局与密度 |
| --- | --- | --- |
| 社区阅读 | 首页、群组帖子、公告、通知、收藏、活动说明 | 首页继续分段实底信息流；公告目录和文字内容优先连续阅读列表，段内分隔。标题 15px、摘要 13–14px，单项常用 16–20px 内边距；只显示必要元信息。群组发现和活动目录可以保留最小 280px 的自适应网格，不能强制全部改成一列 |

## 14. 详情、表单与任务反馈

沿用当前 DetailLayout：workspace ≥880px 才分主/辅栏；辅助栏 `clamp(280px, 26%, 400px)`、间距 32px、sticky 顶距 76px，超高侧栏取消 sticky。阅读宽度限制在主栏内部，不能收窄整体标题、操作和详情表面。

| 场景 | 桌面 | 手机内容顺序 |
| --- | --- | --- |
| 帖子、公告 | 主栏标题/正文/回复，辅栏来源、发布时间和返回入口 | 标题与必要来源 → 正文 → 互动/回复 → 补充信息；不把全部作者信息机械搬到正文前 |
| 反馈 | 主栏问题和讨论，辅栏真实状态、分类与处理记录入口 | 标题 → 当前状态及处理记录入口 → 问题正文/回复 → 其余信息。可以在页首复用真实状态摘要，完整信息仍保留；不复制两套可失步的状态数据 |
| 活动 | 说明与报名信息分工清晰 | 时间、地点、名额/真实报名状态及操作 → 长说明；状态判断仍来自现有时间/服务逻辑 |
| 空间/预约 | 时段和申请任务实底，结果与进度持续可读 | 空间/日期/当前状态 → 时段选择或结果摘要/下一步 → 用途、长说明、日志。排队不写成成功确认，网络重试不清除已有申请 |
| 后台编辑/审核 | 列表、编辑任务按容器划分；短审核用现有 Modal，长 Markdown/图片表单用独立新建与编辑路由 | 列表右上角新建入口；记录操作进入编辑页。保留取消、校验、原值、保存结果和返回列表位置 |
| 个人设置、宿舍问卷 | 沿用 SettingsSection 与实际问卷分类 | 标签和说明常驻 → 字段 → 关联错误 → 当前区提交结果；不把必须填写的信息藏入装饰性折叠块 |

表单沿用已有字段、默认值、权限和提交流程；不在本轮设计中新增业务字段或强制多步向导。编辑器在自身 ≥720px 才并排预览，窄屏按编辑与预览顺序呈现。主要操作使用动词与对象；危险操作独立且保留现有确认。pending 保持输入和按钮标签，结果错误留在相关表单/模态内。

已知余额、价格、库存和状态一起支持商城决策：余额不足应就近解释，不能只是无说明的灰按钮；余额未知应展示读取状态，不以 0 推断不足。前端提示不能代替服务端校验，也不能假定当前兑换行为经过确认弹窗——现有商城按钮直接发请求，本轮不新增兑换流程。抽卡费用与失败原因同样清晰，但不能伪造尚未读取的余额。

服务未就绪与明确无权限分开表达。预约管理在身份尚未读取时不能把服务错误包装成无权限结论；保留重试、已知数据与现有导航。恢复预约服务、修复接口或修改角色判断属于独立实施任务，不是本次文档已完成的修复。

## 17. 背景与毛玻璃专项复核

专项验收必须保留以下可比较证据：

1. 同一构建、数据、viewport 和主题，分别截图背景渐变开/关；确认静止页面的主基调仍是中性紫灰，正文和图片不被染色。

3. 游客、登录工作区在首屏/滚动后分别检查；有内容/空态，浅/深，桌面/390px 各有代表样本。不以 source alpha 或 computed `backdrop-filter` 代替截图判断。
4. Modal、命令菜单、移动抽屉分别检查打开/关闭；后方导航色调连续、前景边缘清晰、字段和长文可读。`::backdrop` 和内层背景一起核查，不孤立批准 Floating 的 alpha。
5. 仍遵守既有对比度、可见 blur 数量、20px 上限及性能预算。当前参数已同步到令牌；后续变更继续保留同条件对照，不用历史基础检查结果替代新参数的验证。

## 18. 页面组合与管理列表

业务范围切换使用群组页同款下划线页签。公告、活动、商城、成就和卡片管理的列表统一提供 coeer-tabs coeer-scope-tabs coeer-scrollbar 范围页签和 coeer-filter-panel；活动报名、商城兑换详情各自放在范围页签。范围切换不承载管理表单，新建与编辑仍使用独立路由；列表右上角放置新建按钮，记录上的编辑操作跳转到对应编辑页。筛选条件统一使用 coeer-filter-options，置于搜索工具条之外。保存失败保留草稿，保存或取消后返回原列表页码。整卡链接保留独立子操作。筛选标签通过字重与分隔区分，Select选项悬停用primary实底，表格th/td垂直居中。

反馈目录以独立状态卡片网格代替整页大面板，范围页签和筛选直接排在画布；预约导航跟随各页标题下方，只含空间目录／我的预约。首页提交反馈属于第三个快捷入口。收藏采用标题、搜索/类型、摘要卡片、分页；群组来源在卡片内，搜索与类型在服务端按当前权限过滤后再分页，清除与翻页保留正确URL状态。

宿舍执行、问卷记录、创建为独立路由，分配页不嵌创建表单或提交名单。所有列表搜索使用共同工具栏，不包进卡片；废止已选条件摘要行和其样式。清除入口固定占位，搜索/清除前后工具栏高度稳定，桌面与390px分别验收。

管理页面和前台列表使用 `PageLayout`，页面间距来自 `--section-gap`，标题与右上角操作由 `SectionHeader` 统一渲染。新建、编辑页通过 `AdminEditorLayout` 复用此容器；嵌套管理面板可以省略标题。

状态列表使用 `DataTable`：统一表头、行高、列间距、空态和手机横向滚动提示。操作列使用 `RowActions`，状态与公开性分别使用 `StatusBadge`、`VisibilityBadge`。复杂预约处理、空间编辑保留在详情弹窗中，列表只承载摘要与状态。

`FilterPanel` 管理范围、搜索和清除筛选；每组筛选由 `FilterOptions` 渲染，`filterGroup` 构造“全部 + 类型选项”。筛选选项始终位于搜索工具条之外。反馈范围为“已审核反馈 / 审核队列”，群组范围为“已审核群组 / 审核队列”；前者显示编辑、删除，后者显示审核、删除。群组的已审核范围包含通过与驳回，状态筛选不包含待审核。列表和总数共用服务端范围条件。

`PageLayout` 直接接收 `title`、`description`、`action`、`scope` 和 `filters`，依次渲染 `coeer-page-header`（含可选 `coeer-page-actions`）、scope 页签、`coeer-filter-toolbar`、`coeer-filter-groups` 和业务内容。页面只传数据、回调和内容，不再自行拼接 `SectionHeader`、`ViewTabs`、`FilterPanel`。统一间距继续使用 `--section-gap`。

前台群组、公告、通知、收藏、活动、反馈、商城、卡片、成就、个人中心，以及后台反馈、群组、公告、活动、商城、成就和卡片管理均采用此布局。新增、编辑和详情页可以省略不适用的 scope 与筛选；通知只有 scope，个人中心没有筛选，不生成空工具栏。公告、活动、商城和收藏列表提供“全部…”范围。

动态、空间预约、宿舍，以及后台工作台、宿舍、空间、统计保留专用内容结构，同时复用页面容器和适用的标题、筛选配置。特殊欢迎区或空间标题/导航组合使用 `header` 插槽，它始终位于筛选之前；常规页面使用标准标题属性。`as` 可保留详情页的 `article` 语义。
