# 社区互动、通知与密码管理

列表筛选中的分组标题使用独立样式。反馈范围、帖子类型和通知筛选不再附带数量；反馈、帖子、
群公告、活动、公告、群组、卡片与成就、收藏、商城及积分流水均在底部分页处显示当前范围的总数。
卡片、我的群组和积分流水在数据库中先筛选再分页，不再只读取前 100 条。公开反馈显式限定
`is_public = true`，列表与计数使用同一条件；本人未公开反馈只出现在“我提交的”。

成员名单的状态筛选只作用于入群记录，查看“待审核”不会把群组本身当成待审核群组查询。
群组列表（公开、我加入的、我管理的、申请中）及详情统一统计已通过审核的成员，
不包含待审核或已拒绝申请；审核和退群后重新查询会更新人数。顶层回复和各层同级子回复
均按发布时间倒序，加载更多保持该顺序，编辑不改变原发布时间。

内置的初次发声、社群发起人和卡片收藏家成就会在反馈提交、群组创建/管理员变更、抽卡时自动检查。
访问成就页也会按已有业务数据补发，重复检查不会重复解锁；收藏家按拥有数量大于零的不同卡片种类计数。
成就页显示实际条件进度，抽卡后刷新卡册和成就状态。新增成就代码需要同时实现对应的条件判定。

活跃积分由服务端确认行为后发放，个人中心可查看规则与完整流水：每日访问 +5（1 次/日）、
提交反馈 +10（2 次/日）、发帖 +5（3 次/日）、回复 +2（5 次/日）、活动签到 +20（3 次/日）。
每日额度按北京时间零点重置；发帖和回复分别计额，签到由主办方或管理员确认，同一活动只奖励一次。
奖励使用稳定事件编号防止重复发放，并按用户串行检查限额；业务写入、奖励和成就处于同一事务。
这部分改动复用已有表和积分来源，无需额外数据库迁移。

已有数据库运行 `pnpm db:upgrade:community`，以增量方式创建 `notifications`、
`password_resets`、`bookmarks` 表及索引。命令可重复运行，不删除已有业务数据；新环境也可使用
`pnpm db:push`。本次本地数据库已完成升级，发布脚本仍不自动执行数据库变更。
发布构建前会通过 `pnpm db:check:community` 检查这些表和字段，缺失时阻止切换；
`/healthz` 也检查表结构，避免仅数据库连接成功就报告健康。生产升级步骤见 [deployment.md](deployment.md#已有数据库的社区功能升级)。

动态、群组帖子列表和详情均支持点赞/取消点赞和收藏/取消收藏，显示本人状态；游客操作
会进入登录页。“我的收藏”（`/bookmarks`）支持分页，退出私密群后不再展示其内容。
收藏记录由数据库保存，帖子删除时自动清理。

动态中不提供回复；群组帖子详情提供群内回复，只有已通过审核的群成员可以发表、查看
和编辑自己的回复。群管理员和平台管理员可删除不当回复，删除后保留占位与后续对话；
管理员不能冒充作者编辑回复。所有读取入口、作者历史、子回复与写操作均检查群内权限，
不能跨帖引用父回复，也不能通过反馈接口发表回复。群管理员可审批/拒绝申请、调整角色、
移除成员、管理帖子与群组设置；并发成员变更使用群组行锁，始终保留至少一名管理员。

帖子及回复、公告、反馈正文和活动说明支持基础 Markdown 与 LaTeX（`$…$` 行内、
`$$…$$` 独立公式），兼容普通文本换行。禁用原始 HTML、危险链接及受信任 LaTeX 命令。
发帖与编辑、群公告、回复、反馈提交、公告管理和活动管理使用统一的实时预览编辑器；
预览随输入、编辑对象切换及表单重置同步更新，公告和活动保存失败时保留草稿。
公告、反馈和活动列表摘要也渲染 Markdown 与公式；可点击卡片的摘要不嵌套正文链接。
`pnpm seed:community` 会增量添加编程学习小组的“求助：这题怎么积？”演示帖子。

站内通知位于 `/notifications`，顶部铃铛每 30 秒更新未读数，也会在页面重新获得焦点时
刷新。支持全部/未读列表、分页、单条与全部已读；通知只能由收件人访问。反馈状态变化、
群组审核、入群审核和报名成功在对应业务事务内写入通知，事务失败不会产生消息。

活动在查询列表、筛选、计数或详情时将到期状态写回数据库，浏览中的卡片和详情也按
当前时间刷新。已完成和已取消状态保留。报名事务会重新检查时间并锁定活动，避免过期报名、
并发超额；取消报名后再次报名会复用原报名记录。列表和详情的已报名项提供“取消报名”
按钮，已签到项保持“已签到”。重复提交报名不会重复创建记录或通知。管理员可正常报名，
展示学号为保留的 `0000000000`，仍受报名时间和名额限制。

登录页“忘记密码？”进入 `/forgot-password`；侧栏“设置”进入个人中心，可修改昵称与密码。
找回密码需要在忽略的 `.env.local` 或运行环境中配置：

```dotenv
APP_URL=http://localhost:3000
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=coeer@example.com
SMTP_PASSWORD=your-mail-service-password
SMTP_FROM=COEER <coeer@example.com>
```

生产环境 `APP_URL` 必须使用 HTTPS；465 端口使用 TLS，其余端口强制 STARTTLS。
SMTP_USER/SMTP_PASSWORD 可同时省略以连接允许无认证的内部邮件中继。
未配置或发送失败时，页面明确提示服务不可用。自动测试使用模拟发信服务验证成功、失败、
过期、一次性使用及会话失效。

重置链接的令牌放在 URL fragment 中，避免进入 HTTP 请求地址或 Referer；数据库仅存摘要，
有效期 30 分钟。按邮箱摘要持久化限制为每分钟一次、每小时最多五次，未知邮箱使用同样的
申请响应与限流记录。密码变更或重置后，旧会话和旧重置链接立即失效。

`pnpm seed:all` 以增量方式补齐演示数据，修复已知演示图片、公告引用、活动主办方、
反馈时间顺序和积分说明；重复运行不重置账号密码或重复发放积分。活动包含即将开始、
进行中、已结束、已取消及名额已满的样例；图片来自 `public/demo`。种子禁止在
`NODE_ENV=production` 下运行。`--clean` 仍会清除业务数据，只应用于可重建的演示库。
旧数据库保留的六种 `placehold.co` 演示图片地址在展示时直接使用对应本地 SVG，
生产环境无需重跑种子修复卡片和商城图片，自定义图片地址不受影响。

对已部署实例补充演示数据可在本机运行 `pnpm run deploy:db:seed --user test@example.com`。
它自动备份后只向指定的已有启用账号增量添加演示群、帖子、收藏、通知、卡片、成就和
一次性 200 测试积分；可重复运行，不创建默认密码账号，不清理业务数据。与本地
`seed:all` 使用固定账号的流程不同。数据库状态、备份与升级命令见 [deployment.md](deployment.md#部署数据库命令)。

本机加密账号、会话及密钥已移入 Git 忽略的 `.coeer-local`；Vite 禁止通过 HTTP 读取此目录，
部署打包同样排除该目录。服务端继续允许读取仓库外的私密文件，便于使用现有生产部署配置。
