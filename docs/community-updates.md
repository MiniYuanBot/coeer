# 社区功能与配置

## 列表与群组交流

反馈、群组、帖子、公告、活动、收藏、卡片、成就、商城与积分流水支持筛选和分页。
总数只在底部分页显示，使用与当前列表相同的筛选和可见性条件。
公开反馈只包含 `is_public=true` 的记录；本人的未公开反馈在“我提交的”查看。
后台反馈管理显示“公开／非公开”标识，审核弹窗以记录原有的处理状态和公开性为初值。

公告、活动、商城、成就与卡片管理使用独立的列表、新建和编辑页面。
列表右上角提供“新建”按钮，记录上的“编辑”进入按 ID 加载的编辑页；直接访问或刷新编辑地址仍会加载原记录。
保存或取消后返回列表并保留原页码，保存失败会保留表单草稿。
管理列表统一使用范围页签与筛选面板：公告按置顶、类型筛选；活动的报名情况与商城的兑换详情各有独立范围页签，按活动类型或物品类型筛选。
成就、卡片管理可切换全部、公开、隐藏范围，并分别按成就类型、卡片稀有度筛选。

前台卡片位于 `/cards`，成就位于 `/achievements`，分别提供全部与本人获得／达成的范围。
公开成就与卡片在未获得时也可见；隐藏成就仅对已达成者显示，隐藏卡片仅对持有数量大于零的用户显示。
可见性条件在服务端搜索、分页与计数之前应用；隐藏卡片仍按原权重参与抽取。
现有数据升级后默认公开，可在新建、编辑表单中更改。升级命令为 `pnpm db:upgrade:community`。

群组发现仅列出已审核通过的公开群组，名称和介绍支持关键词搜索。
输入完整且大小写一致的 slug 可找到对应的已审核群组（含私密群组），部分 slug 和通配符不会匹配。
找到私密群组后可申请加入，内部帖子仍需通过成员权限检查。
待审核的入群申请在群组主页显示不可重复点击的“已申请”，刷新后仍保持申请状态。
动态和按作者列出的帖子仅包含已审核公开群组的公告与讨论，私密内容不参与分页或计数。
平台群组审核使用独立接口，并在服务端检查平台管理员身份。

群组人数只统计已批准成员，不包含待审核或已拒绝申请。
成员状态筛选仅作用于入群记录；审核或退群后重新查询会更新人数。
帖子详情中的顶层回复和各层同级回复按发布时间倒序，编辑不改变排序时间。
群成员可发布和查看回复，作者可编辑，作者及管理人员可删除；删除父回复会保留占位和后续对话。

帖子可点赞和收藏，“我的收藏”在 `/bookmarks`。失去私密群访问权限后，对应内容不再出现在收藏中。
正文编辑器支持基础 Markdown、行内公式 `$…$` 和独立公式 `$$…$$`，提供实时预览。
原始 HTML、危险链接和受信任 LaTeX 命令禁用，保存失败时保留草稿。

## 成就与活跃积分

管理员在成就管理中选择条件并填写目标数值，成就代码可留空自动生成，无需编写程序。
支持注册即得、累计登录天数、累计获得积分、累计提交反馈、创建或管理群组数、收集不同卡片数。
例如选择“累计登录天数”并填 `100`，或选择“累计获得积分”并填 `10000`。

注册即得在注册成功时发放，目标值固定为 `1`。登录天数依据每日活跃积分记录，按北京时间
统计不同日期，同日重复登录或访问只算一天，无需连续；已有记录会计入，未记录的历史日期不推算。
累计积分统计历史正数收入，兑换或抽卡消耗不会减少进度。
收藏家按拥有数量大于零的不同卡片种类计数；群组统计创建或以管理员身份管理的非驳回群组。

相关行为完成后检查解锁；访问成就页也会按已有业务数据为符合新规则的老用户补发，重复检查不重复发放。
原有初次发声、社群发起人和卡片收藏家的旧规则仍可使用。

## 抽卡与卡片管理

管理员可从运营中心或侧栏进入 `/admin/cards`，添加、编辑卡片的名称、说明、系列、稀有度、
卡面及抽中权重。卡面是必填项，可上传本地图片或使用有效图片链接。
权重范围为 `0–1`，最多四位小数，实际概率为该卡权重占奖池总权重的比例；
例如 `0.6、0.3、0.1` 对应 `60%、30%、10%`。稀有度用作展示分类，不额外改变权重。

将权重改为 `0` 即移出奖池，已有收藏保留。没有正权重卡片时不抽取、不扣积分。
每次抽卡消耗 50 积分，扣款与卡片入账在同一事务完成；结果弹窗显示本次获得的卡片和消耗。
收藏卡片与结果卡面均采用 3:4 竖向画框，旧图片完整放入画框，不自动截掉内容。

## 图片尺寸与裁剪

卡片、成就、商城管理均提供“选择本地文件”按钮及下方的拖放区域，支持 PNG、JPEG、GIF 或 WebP
原图，单张不超过 5 MB。字段旁显示固定展示比例和建议尺寸：

| 用途 | 展示比例 | 裁剪输出尺寸 |
| --- | --- | --- |
| 抽卡卡面 | 3:4 | 600 × 800 像素 |
| 成就图标 | 1:1 | 512 × 512 像素 |
| 商品图片 | 16:9 | 960 × 540 像素 |

选择或拖入后打开裁剪预览，可用鼠标或触屏拖动位置、调整缩放，或用方向键移动。
确认后生成约定尺寸的 PNG；GIF 裁剪后转为静态图片。原图较小时提示清晰度可能下降。
取消不会覆盖原图片或表单内容；确认后可再次调整裁剪，也可移除或展开填写图片链接。
已保存的外部链接只有允许跨域读取时才能在浏览器裁剪，否则可下载后再选择本地文件。

无效文件不会覆盖已选图片，上传或保存失败时保留表单草稿。图片在保存表单时上传，
服务端检查管理员权限、大小与文件格式，返回可用于卡面、图标和商品的图片地址。
成就卡片会展示已配置的图标，商城后台可编辑所有状态的商品，包括售罄与已下架商品。

图片内容保存在 `uploaded_images` 数据库表中，随数据库备份与恢复，不依赖发布目录。
替换、移除图片或删除上传者不会删除已保存的图片，以便已有引用继续访问。

## 活跃积分

| 行为 | 积分 | 每日次数上限 |
| --- | --- | --- |
| 访问社区 | +5 | 1 |
| 提交反馈 | +10 | 2 |
| 发帖 | +5 | 3 |
| 回复 | +2 | 5 |
| 活动签到 | +20 | 3 |

每日额度按北京时间零点重置。签到由主办方或管理员确认，同一活动只奖励一次。
奖励按用户串行核对限额，以稳定事件编号防重复；业务、奖励和成就写入同一事务。
个人中心可查看规则和完整积分流水。

## 通知与活动

`/notifications` 提供全部、未读、分页和已读管理，通知仅收件人可访问。
铃铛每 30 秒及页面重新获得焦点时刷新未读数。反馈状态、群组审核、入群审核和报名成功
会在对应业务事务中写入通知。

活动按时间显示即将开始、进行中或已结束，过期后关闭报名。
报名检查容量，取消后释放名额并允许重新报名；签到和名单受主办方与管理员权限限制。

## 密码与邮件

`/profile` 修改昵称和密码，`/forgot-password` 申请密码找回。
在环境文件或运行环境中配置：

```dotenv
APP_URL=https://coeer.example.com
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=coeer@example.com
SMTP_PASSWORD=your-mail-service-password
SMTP_FROM=COEER <coeer@example.com>
```

生产 `APP_URL` 使用 HTTPS。465 端口使用 TLS，其余端口强制 STARTTLS；
允许匿名的内部邮件中继可同时省略用户名和密码。未配置或发信失败时，页面提示不可用。

重置令牌放在 URL fragment，数据库只存摘要，有效期 30 分钟且只能使用一次。
同一邮箱每分钟最多申请一次、每小时五次，未知邮箱使用相同的响应和限流方式。
密码修改或重置后，旧会话和旧重置链接失效。

## 管理界面统一

- 反馈管理区分已审核反馈与审核队列，状态筛选在数据库分页与计数之前生效。审核、编辑弹窗保留原状态与公开性，保存失败保留输入，成功后重新加载列表。
- 修复原生弹窗在 React StrictMode 重放 effect 时，被延迟关闭事件误关的问题。
- 群组后台分为“已审核群组 / 审核队列”。已审核包含通过与驳回，提供编辑和删除；队列提供审核和删除。支持类型、公开性和审核状态组合筛选，列表和总数共用条件。旧待审核链接仍可用。
- 管理列表统一使用 `DataTable`、`RowActions` 和状态标签；页面与筛选布局复用 `PageLayout`、`FilterPanel`、`FilterOptions`。空间预约与配置的详细操作移入弹窗。

共享布局与审核分区不需要迁移；卡片、成就的隐藏字段需要执行下述升级。

## 表结构升级

```sh
pnpm db:check:community
pnpm db:upgrade:community
```

增量升级补齐通知、密码找回、收藏、图片存储表、成就条件类型及卡片/成就的 `is_hidden` 字段，可重复运行。已有部署应先执行升级，
再发布包含新条件与图片上传的版本。线上命令见
[deployment.md](deployment.md#数据库状态与升级)。
