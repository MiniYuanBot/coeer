# COEER 界面审查与优化

本轮优化沿用 React 19、TanStack Start 与 Tailwind CSS 4，保留浅色默认、深色切换和现有业务接口。优先统一导航、页面边界、内容宽度和筛选组件，再调整具体页面的信息密度。实现规范见 [DESIGN.md](../DESIGN.md)。

## 参考依据

- [Linear 界面重设计](https://linear.app/now/how-we-redesigned-the-linear-ui)：参考应用外壳、对齐、导航密度和视图层级；采用其产品界面的组织方式。
- [shadcn 组件](https://ui.shadcn.com/docs/components/sidebar)与 [Blocks](https://ui.shadcn.com/blocks)：参考可组合的侧栏与布局边界，继续复用项目现有组件。
- [Vercel Web Interface Guidelines](https://vercel.com/design/guidelines)：用于核对键盘操作、可见焦点、移动触达尺寸、输入字号及 URL 状态。
- [Mobbin](https://mobbin.com)的公开页面用于了解参考库的模式分类；[Page Flows](https://pageflows.com)返回 403，本轮未引用其受限流程内容。

## 问题与实施结果

| 优先级 | 审查发现 | 实施结果 |
| --- | --- | --- |
| 高 | 外壳路径栏与内容的左边界不一致；详情和表单有的居中、有的靠左 | 外壳尺寸使用统一变量；PageLayout 区分完整画布、896px 阅读区、704px 表单区，统一左对齐 |
| 高 | 卡片列数按视口切换，1024px 屏幕扣除侧栏后仍放三列，标题和短状态被挤压 | 网格按实际内容宽度自动分列，最小列宽 280px；短徽章禁止换行 |
| 高 | 宽屏筛选仍固定分成搜索和筛选两行 | FilterPanel 随空间并排或换行；手机搜索独占一行 |
| 高 | 管理子页面缺乏连续切换入口，必须反复回工作台 | 后台侧栏显示管理模块与返回社区入口；面包屑提供可点击父级 |
| 高 | 后台反馈页直接读取路由 pending，首屏服务端和客户端产生不同的“刷新中”标记 | 使用响应式路由订阅，并在 hydration 后显示更新状态，消除首屏不一致 |
| 高 | 个人中心展示写死的 3 个群组、8 条反馈、2 个成就 | 移除占位统计，使用真实身份、角色、余额与积分记录 |
| 中 | 表单宽度、标签和取消按钮顺序不统一；后台非受控字段切换编辑对象时可能保留旧值 | 创建群组与反馈复用字段组件；后台添加持久标签并按编辑对象重建字段；取消位于提交前 |
| 中 | 群组成员和帖子页显示无法执行搜索的输入框 | 保留可用筛选，仅在具备搜索能力时渲染搜索表单 |
| 中 | 群组导航、预约导航和反馈范围的激活态不同 | 群组与预约复用下划线导航；修正激活线被透明边框工具类覆盖的问题 |
| 中 | 集合图片加载失败后留下大块破图区域 | MediaPreview 提供受控尺寸与失败占位；商城余额收进页面操作区 |
| 中 | 手机字段字号偏小，图标按钮和导航触达区域不足 | 字段字号 16px；按钮、主要导航与输入框最小高度 44px；筛选项最小高度 40px |
| 中 | 宽表格缺少局部滚动提示和键盘入口 | TableScroll 检测超宽后提供可聚焦区域、方向键滚动与提示 |
| 中 | 信息流分隔线受到外层链接圆角影响；菜单内留白会触发关闭 | 信息流链接移除多余圆角；抽屉与命令菜单只在真正点击遮罩时关闭 |

## 页面应用

动态页使用受内容宽度控制的双栏与轻量分隔线。反馈页保持状态图标、内容、状态和日期的对齐，手机将状态和日期并入元信息。群组、活动、公告、商品采用自动网格，避免固定列数挤压内容。

详情与填写页使用稳定的阅读宽度，群组子页使用 h2，保留一个页面主标题。个人中心采用资料、安全与积分三个分区；后台概览使用 StatsBar 和紧凑入口行，手机四项指标变为两列。

预约目录、预约记录及后台空间配置继续使用原有数据与权限逻辑。界面显示服务返回的过期快照、不可预约、审核和加载状态。本轮浏览器检查未提交或取消真实预约，也未执行兑换、抽卡或内容删除。

## 可复用规则

| 用途 | 组件或类 | 约束 |
| --- | --- | --- |
| 页面宽度 | PageLayout | full、reading、form；左对齐，间距 24px |
| 带辅助信息的详情与表单 | DetailLayout | 最大画布 1200px，内容区达到 880px 时分出 280px 辅助栏；窄屏堆叠 |
| 标题与操作 | SectionHeader | 主标题 22px；子页可选 h2；手机说明独占一行 |
| 集合 | .coeer-grid | 根据内容宽度排列，最小列宽 280px |
| 搜索筛选 | FilterPanel | 只有真实搜索能力才传入搜索参数；状态仍由调用方写入 URL |
| 页面内导航 | NavTabs | 激活态依赖链接 data-status，自身横向滚动 |
| 同类指标 | StatsBar | 只接受真实数值；以一个容器和分隔线组织 |
| 可选图片 | MediaPreview | 加载失败稳定占位，限制集合媒体高度 |
| 宽表格 | TableScroll | 局部横向滚动，超宽时可键盘聚焦 |

颜色沿用语义令牌，不增加页面专用色和装饰性阴影。开发路由工具默认隐藏，可在本地环境设置 `VITE_ROUTER_DEVTOOLS=true` 启用。

## 验收记录

- `pnpm typecheck` 与 `pnpm build` 通过。
- `pnpm test` 通过：97 项 Vitest 测试、3 项发布脚本测试。
- 27 个主要页面在 1440、1024 和 390px 下完成 81 张截图，未发现页面整体横向溢出。表格在自己的容器内滚动。
- 10 组浏览器交互检查通过：搜索与空状态清除、筛选和浏览器返回、键盘页面搜索、管理编辑与取消、详情和群组导航、手机抽屉及焦点返回、字段字号与原生校验、表格键盘滚动、主题持久化、游客和认证页面。
- 群组导航激活线与无效搜索入口完成 10 个视图复测；反馈页 hydration 与后台概览完成 6 个视图复测，未再出现 JavaScript 错误。

截图、交互记录和对比入口保存在忽略的 `tmp/ui-review/`，本地查看 [截图对比](../tmp/ui-review/index.html)。其中 `before/` 为基线，`after/` 为主要页面，`interactions/` 为详情、弹窗和深色主题，`final-details/` 与 `recheck.json` 为后续修正的复测记录。

## 三个打开页面的布局修正

帖子详情将正文和帖子信息分为两栏，手机操作独立成行，标题可使用完整宽度。活动详情只展示一次标题与说明，时间、地点和报名进入辅助栏，窄屏优先展示报名信息。反馈填写区扩展为正文与提示双栏，将反馈对象和补充信息并排，保留表单校验与提交接口。

这三页分别在 1920、1440、1024、390px 完成 12 张截图检查，无页面横向溢出或 JavaScript 错误；帖子删除确认的关闭和反馈表单原生校验也通过检查。产物位于 `tmp/ui-review/three-pages-after/`。
